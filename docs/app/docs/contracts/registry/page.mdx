# Registry Contract

The Registry contract maintains an on-chain index of every stream and
platform-wide aggregate statistics. It exists so that "list all streams" or
"what's the platform's total volume" can be answered by a single contract
call, without an off-chain indexer walking every `create` event from
genesis. `stellar-stream-hive-api`'s own `/stats` endpoint mirrors the shape
of `get_stats` (computed independently from indexed events, as a
cross-check) -- see [API Reference: Stats](/docs/api/stats).

Source: [`stellar-stream-hive-contract`](https://github.com/Stellar-Hive/stellar-stream-hive-contract)
(contract module `registry`). Deployment addresses are not yet published --
see [Getting Started](/docs/getting-started#deployed-contract-addresses).

## Types

### `RegistryStats`

```rust
pub struct RegistryStats {
    pub total_streams: u64,
    pub active_streams: u64,
    pub total_streamed: i128,
    pub total_withdrawn: i128,
}
```

| Field | Meaning |
|---|---|
| `total_streams` | Count of every stream ever created, regardless of current status. |
| `active_streams` | Count of streams whose last-recorded status is `Active`. `Pending` does not count. |
| `total_streamed` | Lifetime cumulative sum of every stream's committed `amount` at registration. It only ever goes up and is not live accrual. |
| `total_withdrawn` | Sum of `withdrawn` across every stream. |

### `RegistryError`

```rust
pub enum RegistryError {
    AlreadyInitialized = 1,
    NotInitialized = 2,
    Unauthorized = 3,   // caller is not the registered Stream contract
    StreamNotFound = 4,
}
```

## Functions

### `initialize`

```rust
pub fn initialize(env: Env, stream_contract: Address)
```

One-time setup. Records the only contract address permitted to call
`register_stream` and `update_stream` -- the same caller-identity pattern used
by the [Vault's `release`/`refund` functions](/docs/contracts/vault#release), applied here to
protect the integrity of the index rather than custody of funds.

- **Auth:** none beyond "must be called once, at deployment, by whoever
  deploys the Registry" -- there is no separate admin key to rotate this
  later, by design; if the Stream contract is ever redeployed, the Registry
  must be redeployed alongside it.
- **Errors:** `AlreadyInitialized`.

### `register_stream`

```rust
pub fn register_stream(env: Env, stream_id: u64, sender: Address, recipient: Address)
```

Called once by the Stream contract inside `create_stream`, immediately after a
new stream is assigned its id. Adds the id to the sender's and recipient's
lookup indices and increments `total_streams` / `active_streams`.
`register_stream` always records the new stream as `Active`; `update_stream`
can correct the status afterwards (for example to `Pending`).

- **Auth:** none -- anyone can call this function. See
  [Security notes](#security-notes).
- **Errors:** `Unauthorized`.

### `update_stream`

```rust
pub fn update_stream(env: Env, stream_id: u64, withdrawn_delta: i128, status: StreamStatus)
```

Called by the Stream contract after every `withdraw`, `withdraw_max`, and
`cancel_stream` to keep the Registry's aggregate figures correct without it
having to recompute accrual for every stream on every call. `withdrawn_delta`
is added to the Registry's running `total_withdrawn`; if `status` transitions
away from `Active`, `active_streams` is decremented; a transition into
`Active` increments it.

- **Auth:** none -- anyone can call this function. See
  [Security notes](#security-notes).
- **Errors:** `Unauthorized`, `StreamNotFound`.

### `get_all_streams`

```rust
pub fn get_all_streams(env: Env) -> Vec<u64>
```

Returns every stream id ever registered, oldest first. Intended for small
deployments and tooling; for platform-scale queries prefer
[`GET /streams`](/docs/api/streams) on the indexer API, which paginates and
avoids loading the full on-chain vector into a transaction's execution budget.
On-chain, prefer `get_streams_page` over `get_all_streams` for large registries.

- **Auth:** none (read-only).

### `get_stats`

```rust
pub fn get_stats(env: Env) -> RegistryStats
```

Returns the current `RegistryStats`. The Registry keeps these as incremental
counters, so this is a single read: its cost does not grow with the number of
streams. `total_streamed` is the lifetime cumulative committed amount, not live
accrual.

- **Auth:** none (read-only).

### `get_active_streams`

```rust
pub fn get_active_streams(env: Env) -> Vec<u64>
```

Returns the ids of every stream whose last-recorded status is `Active`.

- **Auth:** none (read-only).

## Events emitted

The Registry emits a typed event each time it changes its index, defined in its
`events.rs`. Each event's name is its first topic `Symbol`, and `stream_id` is
the second topic:

| Event | Topics | Data |
|---|---|---|
| `register` | `[Symbol("register"), U64(stream_id)]` | `I128(amount)` |
| `update` | `[Symbol("update"), U64(stream_id)]` | `I128(withdrawn)` |

These are single-value events: the data is the amount itself, not a `Vec`. The
Stream contract's `create`/`withdraw`/`cancel` events remain the lifecycle feed
that `stellar-stream-hive-api` indexes; the API does not need the Registry's
events. The consolidated table lives in
[Stream contract: events emitted](/docs/contracts/stream#events-emitted).

## Security notes

- `register_stream` and `update_stream` take no caller and are intentionally
  open: anyone can call them. The Registry never holds or moves funds, so the
  worst a third party can do is corrupt its statistics and listings. Funds
  safety depends entirely on the Vault's caller check (see
  [Security Model](/docs/concepts/security-model)). See the contract repo's
  [`docs/registry.md`](https://github.com/Stellar-Hive/stellar-stream-hive-contract/blob/main/docs/registry.md) for the rationale.
- Because of that lower stakes profile, the Registry is a reasonable place to
  add caching, pagination, or alternate indexing strategies over time without
  touching the fund-safety-critical parts of the platform.

<CalloutBox variant="warning" title="Registry data is not a source of truth">
  Because anyone can write to the Registry, its stats and stream listings can
  be polluted by third parties. Do not treat Registry data as authoritative;
  verify against the Stream contract.
</CalloutBox>
